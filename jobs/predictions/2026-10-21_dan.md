## The one example everything below uses

Context the model sees:
```

The cow's locker is 5. The dog's locker is 3. The pig's locker is 7.
```
Four kinds of question about it. The **bridge** is the animal the model must find first (here: cow).

| Name | Question | How the bridge is found | How the answer is found | Answer |
|---|---|---|---|---|
| BL | Which locker belongs to Jack's pet? | read from the prompt (Jack -> cow) | looked up in the prompt (cow -> 5) | 5 |
| BR | How many legs does Jack's pet have? | read from the prompt | recalled from memory (cow -> 4 legs) | 4 |
| RL | Which locker belongs to the animal known for mooing? | recalled from memory (mooing -> cow) | looked up in the prompt | 5 |
| RR | How many legs does the animal known for mooing have? | recalled from memory | recalled from memory | 4 |

What we know so far (unverified):
- In RL, the lens **sees** "cow" in the question's hidden states (95% of items), but pushing the lens's "dog instead of
  cow" direction there does **not** change the answer (<= 3%). In RR the same push works (~36%).
- So for RL the model uses something the lens can read but not steer. Tonight asks: what is that thing, where is it,
  and when is it used?
- Removing the lens's whole "J-space" barely hurts lookups (BL/RL stay ~99%) but breaks recalls (BR/RR drop to ~20%).

## D3. Does the question carry the word "cow", or a pointer like "the 2nd statement"?

**What we do.** Take two prompts. Copy the question's hidden states from one (the source) into the other (the base),
one layer at a time, and see which answer comes out.

**Example.**
```
Base:   The dog's locker is 3. The cow's locker is 5. The pig's locker is 7. The duck's locker is 9.
        Which locker belongs to the animal known for mooing?            -> 5   (cow, 2nd statement)
Source: The pig's locker is 1. The duck's locker is 8. The sheep's locker is 6. The cat's locker is 2.
        Which locker belongs to the animal known for oinking?           -> 1   (pig, 1st statement)
```
Copy the source's question into the base. What does the base now answer?

| If the copied question carries... | the base answers | because |
|---|---|---|
| the word "pig" (identity) | 7 | in the base, the pig's locker is 7 |
| "the 1st statement" (position, a pointer) | 3 | in the base, the 1st statement is the dog's |
| the answer itself, "1" (value) | 1 | the digit travelled along |
| nothing that matters | 5 | the base keeps its own answer |

**Why we care.** If the answer is 3 (position), the model looks things up by *where* they are, not by the word. A
word lens can read the word but cannot change a position: that would explain "read but not steer". If it is 7
(identity), the model does use the word, just in a form the lens cannot push.

## D2. From where, and at which layers, does the model read "The cow's locker is 5."?

answer breaks.

**Example (RL).**

## D1. For BL, did we look in the wrong place?

**What we do.** In BL the bridge is written in the prompt ("Jack's pet is a cow.") and the question only says
"Jack's pet". So far we only measured at the question, where the lens sees the bridge on just 7% of items. Maybe it
lives where it is written. We copy hidden states from a changed prompt into the original, one place at a time.

**Example.**
```
Original: Jack's pet is a cow.  Mia's pet is a dog. ... Which locker belongs to Jack's pet?  -> 5
Changed:  Jack's pet is a dog.  Mia's pet is a cow. ... Which locker belongs to Jack's pet?  -> 3
```
Copy the changed prompt's states into the original, only at:
(a) "Jack's pet is a dog.", (b) just the word "dog", (c) the question, (d) the last tokens.
Where the answer flips from 5 to 3, the bridge is carried there. Then we keep only the lens-readable part of that copy
(the "J-space part") and see if it alone still flips the answer.

**Why we care.** If at the statement the lens-readable part does flip BL, then "lookups go around the J-space" was
partly us measuring at the wrong place. If it does not, the claim holds wherever the bridge is.

## D4. Is a strong early push just "typing the word into the question"?

**What we do.** Earlier, in early layers (16-28), a very strong lens push "dog instead of cow" did change RL answers
(35-61%), and even BL answers, where the lens barely sees the bridge. Maybe the push is just like writing "dog" into
the question. We compare the push with real text edits on the same items.

**Example (RL; original answer 5 = cow's locker).**
| Version | Question | Answer if the model follows it |
|---|---|---|
| push | original question, plus a strong "dog - cow" push in layers 16-28 | 3? |
| name it | Which locker belongs to the dog? | 3 |
| add the word | Which locker belongs to the animal known for mooing, the dog? | 3 or 5 |
| change the clue | Which locker belongs to the animal known for barking? | 3 |
| mention elsewhere | original question, plus "The dog is asleep." in the context | 5 |

We check which edit the push matches item by item (same items flip?), whether it matters which question words get
pushed, and whether later layers look like the edited run.

- **Injection (H-inject):** the push acts like "name it" or "add the word". It works wherever you push in the question
  and moves BL as easily as RL.
- **Real write (H-write):** the push acts like "change the clue". It works mainly on the clue words ("known for
  mooing") and later layers look like the clue-changed run.

**Why we care.** If it is injection, the early-layer result does not contradict the main claim (the lens cannot steer
RL where the model actually uses the bridge). If it is a real write, the main claim gets weaker.
