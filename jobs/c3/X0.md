# X0. Does the lookup let go of the bridge's word form at a depth fixed in advance?

> Status: pre-registered, frozen at the commit that adds this version (named in Dan's batch-25 commit). Decides: whether X1-X4 run, per model. Owner: Dan. Cost: ~4 GPU-h (2x H100). Job specs: `jobs/c3/{x0_necessity_27b_chat,qwen35_9b_x0_necessity,x0_necessity_27b_notemplate}.yaml`.

## 1. Question

On 23 Oct, at the 27B's layer 32, removing the J++-readable part of the bridge's edit stopped hurting lookups, while it kept hurting recalls. That layer was chosen after seeing the data. X0 tests the same thing at layers fixed in advance (27B L32, 9B L12), on fresh scenes, with and without the chat template, and against three other dictionaries.

## 2. Decision rule

Per model; primary set, the bridge's word, chat rendering, J++ at k = 25, the top-token read, point estimates.

| Outcome | Condition (27B L32 / 9B L12) | Fixed | What happens next |
|---|---|---|---|
| confirmed | lookup excess ≤ 0.10 and recall Jdep ≥ 0.30 | 23 Oct (README) | X1-X4 run on this model |
| killed | lookup excess ≥ 0.20 or recall Jdep < 0.20 | 24 Oct (brief), before data | this model leaves X1-X4; if both models are killed, X1-X4 do not run, and the GPU time goes to diagnosing X0 (brief: stop rule) |
| not confirmed | otherwise | 24 Oct (brief), before data | README says "not confirmed"; X1-X4 run only on a model whose lookup is labeled "around" at its predicted layer. **Amended after data (D3 amendment, 24 Oct ~16:05, Appendix B):** the verdict stays; the 27B runs X1-X4 at L32 as reader comparisons under graded rules |
| can't tell | for either reader, the whole edit switches < 30% of items, or fewer than 30 items | 24 Oct (brief), before data | treated as "not confirmed" for the stop rule: this model's X1-X4 legs do not run; no other position or layer stands in for the cell (L28 is not substituted); README says "can't tell" (Dan, 24 Oct ~15:40, before any X0 result was opened) |

**Labels**, per reader, layer and dictionary (reported beside the rule):
- around: excess ≤ 0.10 and its upper bound ≤ 0.20;
- through: Jdep ≥ 0.30 and excess ≥ 0.20, with the lower bound ≥ 0.10;
- otherwise mixed;
- can't tell if the cell is invalid.

The **split** at a layer means the lookup is "around" and the recall "through" on the same items. It is descriptive at every layer except the predicted one.

## 3. Design at a glance

| | |
|---|---|
| Data | `d1_topics_v3`: 600 fresh scenes, seed 24, never read by a model before X0; animals, elements and Greek letters (200 each) |
| Models, layers | Qwen3.6-27B at the word, L16-40 every 2, predicted **32**; Qwen3.5-9B, L6-20 every 2, predicted **12**; no 122B |
| Readers | lookup (PP) and recall (PM) on the identical patched context |
| Edit | Δ = h_alt − h_org at the bridge's word, block output of layer L, one row |
| Renderings | chat (decides; the 23 Oct template); raw (`<context>\nQuestion: <q>\nAnswer:`, no instruction, no trailing space), reported beside it. A gate of ≥ 80% unedited org accuracy for both readers applies to each |
| Dictionaries | J++ (main); W_U (logit lens); W_E (input embeddings); random Gaussian. All take k = 25 atoms by signed OMP over the letter-bearing tokens |
| Null | per dictionary: a random subspace taking that dictionary's own share of ‖Δ‖², row by row (rand_sub). Also the random dictionary's own fit (rand_omp, the fitted null) |
| Arms | whole; for each D: without D's part, and without D's random part. At the predicted layer only: J++ and W_E at k = 10 / 50 / 100, and non-negative J++ at k = 25 |
| Read | switch = the top token over the whole vocabulary is the alt answer's first token. Chat: after a space token appended, as on 23 Oct. Raw: the first non-whitespace token the model writes. The cand read (alt first among the digits) is descriptive |
| Metrics | Jdep_D = 1 − S_noD / S_whole; Rdep_D = 1 − S_noRandD / S_whole; excess_D = Jdep_D − Rdep_D; D's share of ‖Δ‖² |
| n | the first 200 eligible scenes per rendering; fewer than 150 = can't test |
| CIs | 95% percentile bootstrap over the org bridge entity, 10,000 resamples, seed 0; Wilson for single rates |

## 4. Data

One scene (animals; lookup and recall on the same context):
- org: "Peter picked the rabbit. The locker of the tick is 2. The locker of the rabbit is 1. The locker of the frog is 5. Noah picked the tick. Iris picked the frog."
- alt: the generator's counterfactual swaps Iris's and Noah's picks: "... Noah picked the frog. Iris picked the tick."

- Recall: "How many legs does Iris's pick have?" 4 → 8.
- Only Iris's pick ("frog") is patched. Where the other changed pick comes first, as here, Δ carries that upstream change too (D5). The asked-first subset is reported.

## Appendix A. Implementation

**Code.** `scripts/x0_necessity.py`: `run` (competence, gate, Δ, parts, reads, then verdict and figures), `verdict`, `figures`; tests in `tests/test_x0_necessity.py`.

**Lens.** The target's pinned J++ (`pins.FROZEN_LENS == "jpp"`; the plain J-lens is used nowhere), at revision e166deb5. 9fa267f8 is gone from the Hub; the 27B file's sha256 is unchanged. The sha256 is checked on load and recorded in every manifest.

**Dictionaries** (`dictionary()`). The atoms are the letter-bearing tokens (`model.letter_token_ids()`), as unit rows:
- J++ = unit((W_U[t] ⊙ g) · J_L);
- W_U = unit(W_U[t] ⊙ g);
- W_E = unit(embed_tokens[t]);
- random = unit Gaussian rows, seed 777 + L, drawn on the CPU.

The fit is `exp04_brew_parts.signed_omp`, plus `bridge_jspace.omp.nonneg_omp` for the non-negative arm. The random subspace is `statement_positions.random_subspace_part`, with its basis seeded 888 + L and drawn on the CPU. The 23 Oct draws were on CUDA, so the tensors differ from 23 Oct.

**Cases** (`build_cases`, `scene_case`). A scene needs both readers, with the same context and cf. In org and alt, the asked person's bridge is one token at one position. The readers' prompts are identical through the bridge, so one Δ serves both. The org and alt answers have distinct first tokens. Drops are counted by reason.

**Eligibility** (`gate_and_eligible`). Org and alt are right for both readers, unedited. Right means two things: the greedy text's first number is the answer, and the decisive read's token is the answer's first token. This is the brief's section 2 condition. The 23 Oct necessity runs also required each hop's own prompt to be right (`tasks_v2.eligible`); X0 does not, because tasks_v2's competence run has no raw rendering. Eligible scenes are taken in scene order up to 200, with at least 150.

**Gate.** Unedited org accuracy under the decisive read is ≥ 0.80 for PP and PM, on all cases of the rendering. The greedy text's and the cand read's accuracy are reported beside it.

**Read** (`read_logits`, `read_row`).
- Chat: one forward of the prompt plus a digit's space token.
- Raw: the prompt ends at "Answer:". If the top token's decode is whitespace only (special tokens excluded), it is appended and the prompt is read again. At most 3 such tokens are skipped (`RAW_STEPS = 4`), and the number skipped is logged per row.
- Each row logs: switched (top token), cand_switched, cand_org_first, role (b / A / other), p(org), p(alt), logit(alt) − logit(org).
- Edits are applied at layer L on every forward of the uncached prompt.

**Examples.** Ten random rows per rendering and layer (seed 0) generate 8 greedy tokens each for whole, without J++ and without J++'s random part.

**Seeds.** Data 24; random dictionary 777 + L; random subspace 888 + L; bootstrap 0; examples 0.

**Cost** (basis: x0_hw_gate_27b, ~7.8k reads in 7 min on this box's H100; on an A100, d1_topics2_parts_27b ran 20k reads in 1505 s).

| Job | Reads | Est. GPU-h |
|---|---|---|
| x0_necessity_27b_chat: 200 × 2 readers × (13 layers × 9 arms + 15) + competence | ~55k | 1.0 |
| qwen35_9b_x0_necessity: chat and raw, 200 × 2 × (8 × 9 + 15) each; raw up to ~2 forwards per arm | ~70k | 0.7 |
| x0_necessity_27b_notemplate (raw): as chat, up to ~2 forwards per arm | ~55-110k | 1.8 |

27B chat and the 9B start together on the two GPUs; 27B raw follows on the first GPU that frees.

**D3 amendment** (Dan, 24 Oct ~16:05 Paris). This is **a change made after data**: after the X0 verdicts (27B NOT CONFIRMED at L32, 9B CONFIRMED at L12) and the interim tables, and before any X1-X4 run.
- **The X0 verdict is unchanged.** The rule at L32 reads "not confirmed" for the 27B, and it stays "not confirmed" in every report.
- **The resource gate changes.** X1-X4 run on the 27B at L32, the pre-registered layer (not L30), re-framed as reader comparisons. Why: the categorical premise (the lookup does not use J++) failed. But the graded contrast is large (at L32 the recall's excess is 0.74 against the lookup's 0.14), J++-specific (W_U, W_E and random are inert at k = 25), and measured on the identical edit and removed part.
- **Wording.** The lookup-vs-recall difference is a "graded contrast". "Split" is used only where the labels say lookup "around" and recall "through" at the same layer.
- **Graded rules.** Each is committed to its spec before its run.
  - Contrast: C = recall excess − lookup excess, paired over the same items, with a bootstrap CI over entities.
  - **X3** holds if C ≥ 0.30 with lower bound ≥ 0.15; fails if C ≤ 0.10; otherwise mixed.
  - **X2'**: r = (excess_K − excess_lookup) / (excess_M − excess_lookup). H-source if r ≤ 0.33; H-know if r ≥ 0.67; otherwise mixed. Can't tell if excess_M − excess_lookup < 0.30.
  - **X4**: lookup excess(translated) − lookup excess(verbatim). ≥ 0.20 is H-verbatim; ≤ 0.10 is not lexical. Positive control: description − verbatim ≥ 0.20; if it fails, the X4 lookup nulls are uninformative.
  - **X1**: among the lookup items that still switch without the J++ part at L32, the share lost when the rebuilt J++ form is removed over L33-44 (arms b and c), minus the same with random parts. ≥ 0.20: rebuilding matters; ≤ 0.10: it does not.
- **Priority**: X2' and X4 first, then X1, then X3 (Zach already has natural-text evidence). The follow-ups use the L32 table (`results/x0_necessity/x0_necessity_27b_chat/descriptive-*`) as their reference.
